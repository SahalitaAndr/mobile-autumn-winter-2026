# План пары 4 (преподаватель)

**Тема:** `useEffect` + `fetch` → список постов → создание поста.  
**API:** `http://185.233.185.109:8080/swagger/index.html` (без авторизации, CRUD `/api/v1/posts`, `/health`).

## Тайминг (~90–100 мин)

| Мин | Что |
|---|---|
| 0–10 | Проверка ДЗ: счётчик, `useEffect`-лаба (таймер/фейк-загрузка) |
| 10–20 | Swagger вживую: GET список, GET по id, показать JSON и поля |
| 20–55 | Лаба `PostsScreen`: `api.ts` → `useEffect` → `FlatList` → loading/error |
| 55–65 | Перерыв |
| 65–85 | `CreatePostScreen`: TextInput (из пары 3) → POST → вернуться и обновить список |
| 85–95 | ДЗ, вопросы |

## Открыть пару

> «Дома вы делали фейковую загрузку через `setTimeout`. Сегодня то же самое, но данные настоящие — с сервера курса. Это первый шаг к приложению с постами.»

## На что смотреть

- `fetch` внутри `useEffect`, а не прямо в теле компонента (иначе бесконечные запросы)
- Массив зависимостей `[]`
- Три состояния: `loading`, `error`, `posts`
- `keyExtractor={item => String(item.id)}`
- Базовый URL вынесен в `api.ts`, не размазан по экранам
- Проверка `res.ok` перед `res.json()`

## Риски

- **CORS:** сервер не отвечает на preflight → в Expo web POST не пройдёт. Только Expo Go / эмулятор.
- **HTTP, не HTTPS:** в Expo Go работает; для сборки (`eas build`) понадобится HTTPS или разрешение cleartext — сейчас не трогаем.
- **Общая база:** все студенты пишут в одни и те же посты. Попросить писать в `title` свою фамилию и не удалять чужое. DELETE/PUT показывать только на своих постах.
